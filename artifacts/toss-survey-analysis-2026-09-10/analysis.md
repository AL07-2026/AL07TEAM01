# 토스 설문을 참고한 에듀핀 질문지 구조·디자인 제안

관찰일: 2026-09-10. 토스 시작 → 가상 닉네임 → 5개 질문 → 결과 및 후속 행동을 직접 확인했다. 에듀핀은 현재 공개 화면과 로컬 문항 정의를 함께 확인했다. 이 문서는 제안이며 질문·계산·서비스 코드를 변경하지 않았다.

**추천 방향은 ‘한 번에 하나의 판단에 집중하는 화면’과 ‘중간에 쉬었다 돌아올 수 있는 긴 질문지’를 결합하는 것이다.** 에듀핀의 우선 과제는 시작 부담, 척도 해석 부담, 입력 손실을 줄이는 일이다. 토스의 5문항과 에듀핀의 127~131묶음은 길이와 목적이 다르므로, 화면만 비슷하게 만든다고 같은 완주 경험이 생기지는 않는다.

## 1. 직접 확인한 흐름

| 단계 | 화면·행동 | 관찰 평가 |
|---|---|---|
| 1 | 시작 | 제목·설명·단일 시작 버튼으로 행동이 명확하다. |
| 2 | 닉네임 | 입력 전 다음 버튼이 비활성화된다. 개인화의 재료지만 진입 단계가 하나 늘어난다. |
| 3 | 질문 1: 구매 상황 | 한 화면에 상황 하나와 문장형 선택지 4개. |
| 4 | 질문 2: 예상 밖 수입 | 같은 틀을 유지하고 진행 번호만 바뀐다. |
| 5 | 질문 3: 지출 상황 | 익숙한 생활 장면을 바탕으로 답하게 한다. |
| 6 | 질문 4: 주거 선택 | 형식은 일관되지만 해당 경험이 적으면 답하기 어려울 수 있다. |
| 7 | 질문 5: 모임 정산 | 선택하면 결과로 연결된다. |
| 8 | 결과 | 유형명·삽화·설명을 한 이미지 카드에 묶고, 아래에서 닉네임으로 부른다. |
| 9 | 후속 행동 | 저장 안내, 행사 연결, 재시작, 공유가 제공된다. 저장·공유의 실제 실행은 하지 않았다. |

질문 화면은 `현재/전체` 진행 번호와 자동 전환을 사용하며, 관찰한 화면에는 이전 질문으로 가는 별도 버튼이 보이지 않았다. 디자인은 회색 바탕, 흑백 타이포그래피, 넓은 여백, 가는 테두리의 직사각형 답변, 둥근 주요 버튼을 조합한다. 흔히 떠올리는 파란색 금융 앱 화면과는 다른 캠페인 디자인이다. [관찰 원본: 토스 금융 성향 테스트](https://toss.im/10to100/financial-personality-test)

이 구성은 판단 대상을 줄이고 결과에 대한 호기심을 유지할 수 있다는 설계적 해석이다. 실제 완주율·전환율 향상은 확인하지 않았다.

## 2. 현재 에듀핀과의 차이

현재 서비스는 미술·창작 인재의 흥미, 최근 행동, 업무·환경 선호, 실제 근무 조건을 구분해 탐색하고 비교하는 질문지다. 지원자와 채용처 질문지는 목적과 응답 방식이 다르다.

| 현재 확인한 구성 | 응답 경험에서 예상되는 영향 | 제안 |
|---|---|---|
| 첫 화면에 버전·검토 설명·대상 전환·문항 수·전체 목차가 함께 노출 | 시작 전에 읽고 판단할 요소가 많다 | 지원자 시작 화면을 별도로 구성하고, 개발·검토 정보는 검토 화면에 둔다 |
| 분야 선택 전 113묶음, 분야 선택 후 기본 127묶음, 아동 접촉 시 131묶음 | 표시 숫자가 바뀌면 끝을 예측하기 어렵다 | 시작에는 조건부 범위를 설명하고 이후에는 장별 진행을 표시한다 |
| 기본 정보 다음에 보수·요일·계약 등 상세 조건 | 자기 탐색의 흥미를 느끼기 전에 입력 부담이 생길 수 있다 | 상세 조건을 후반으로 옮기는 순서를 사용성 시험한다 |
| 긴 페이지에 모든 문항을 연속 표시 | 위치를 잃거나 척도 설명을 다시 찾을 수 있다 | 주제별 진행과 현재 질문의 척도 안내를 제공한다 |
| 새로고침하면 응답 소실 | 긴 질문지에서 중단 후 복귀하기 어렵다 | 임시 저장·이어하기를 우선 구현한다 |

근거: [현재 공개 질문지](https://edupin-questionnaire.vercel.app/), [프로젝트 README](C:/AI_WORKS/EduPin/README.md), [활성 문항·분기 정의](C:/AI_WORKS/EduPin/engine/schema.js), [화면 생성 로직](C:/AI_WORKS/EduPin/tools/browser.js).

## 3. 문항을 유지하는 권장 진행 구조

**시작 안내 → 나의 경험 → 좋아하는 활동 → 최근 일하는 모습 → 편한 일과 환경 → 관심 분야의 실제 상황 → 현실적인 근무 조건 → 답변 검토 → 결과**

| 장 | 이용자에게 보이는 이름 | 현재 문항 매핑 | 기본 묶음 수 |
|---|---|---|---:|
| 1 | 먼저, 지금의 나 | F3 | 10 |
| 2 | 어떤 활동에 마음이 가나요? | R3 | 24 |
| 3 | 최근에는 어떻게 일했나요? | W3 + P3 | 36 |
| 4 | 어떤 일과 환경이 편한가요? | E3 + J3 + X3 | 34 |
| 5 | 관심 분야의 실제 장면 | D3 + S3, 해당 시 N3 | 14 / 18 |
| 6 | 지금 지키고 싶은 근무 조건 | K3 | 9 |
| 합계 | 세부 입력·추가 응답은 별도 | 선택 서술 2개 포함 | 127 / 131 |

위 표는 새 화면에서 묶어 보여주는 제안이다. 현재 순서와 다르며, 문항 내부의 척도·응답 의미·분기·채점 규칙을 유지하는 것이 전제다. 순서 변경이 응답에 주는 영향도 파일럿에서 확인한다.

- **장과 화면을 구분한다.** 36묶음을 한 화면에 쌓지 않는다. 긴 장은 기존 모듈을 경계로 나누고, 반복 척도는 6~10문항마다 쉬어갈 수 있게 한다. 이는 화면 운영 단위의 제안이며 새로운 측정 영역을 만드는 것이 아니다.
- **복잡한 질문은 한 화면에 하나.** 상황형, 양쪽 선호, 조건부 추가 질문은 현재 판단에 집중한다. 반복 5점 척도는 ‘한 문항씩’과 ‘같은 척도 3~4문항씩’을 비교해 편한 쪽을 선택한다.
- **진행 정보는 두 층으로 보여준다.** 예: `2장 · 좋아하는 활동`과 `이 장 8/24`. 전체 범위와 다음 장은 함께 확인할 수 있어야 한다. 조건부 후속 응답은 현재 문항의 하위 단계로 표시한다.
- **중간 휴식은 평가가 아닌 안내로 쓴다.** 예: `좋아하는 활동을 살펴봤어요. 다음에는 최근의 작업 경험을 떠올려볼게요.` 모든 응답이 끝나기 전에 특정 유형이라고 말하면 이후 답을 유도할 수 있다.
- **이전·수정·이어하기를 기본 동선에 둔다.** 단순 선택도 답을 바꿀 수 있어야 한다. 분야를 바꾸면 달라지는 추가 질문과 기존 답의 처리 상태를 안내한다.
- **진행 시간은 실측 후 안내한다.** 현재 추가 입력이 많고 소요시간이 미확정이므로 ‘3분 완성’ 같은 시간을 먼저 약속하지 않는다.

임시 저장은 현재 없는 기능이다. 저장 상태, 실패 상태, 복구 범위, 초기화 방법까지 동작한 후에 `저장됐어요`·`이어서 하기`를 표시한다. 지원자와 채용처는 각각 전용 진입 주소를 제공하고, 기관에는 실제 직무 조건을 기록하는 양식을 제공한다.

## 4. 질문 유형에 맞춘 디자인

| 유형 | 화면 제안 | 반드시 보존할 의미 |
|---|---|---|
| 흥미 5점 | 질문과 5개 선택값, 척도 의미를 같은 화면에 표시 | 하고 싶은 정도와 잘하는 정도를 구분 |
| 최근 행동 5점 | 회상 기간을 질문 위에 짧게 표시 | 최근 행동 빈도와 일반적 자기평가를 구분 |
| 양쪽 선호 7점 | 두 방향 설명 + 1~7 선택 + 별도의 판단 어려움 | 4점과 미경험·판단 어려움을 합치지 않음 |
| 상황형 | 상황 → 행동 하나 → 선택 근거·이유 순으로 펼침 | 행동, 경험 근거, 이유를 각각 기록 |
| 복수 선택 | 선택 개수·상한과 다음 버튼 | 한 번 눌렀다고 자동으로 다음 문항으로 넘어가지 않음 |
| 보수·요일 등 | 단위·값·미정 선택을 관련 입력끼리 묶음 | 미정과 0, 선호와 필수 조건을 구분 |
| 안전 관련 | 별도 맥락과 규정 확인 흐름 | 성격 유형의 점수로 통합하지 않음 |

기존 7점 척도를 보기 좋은 두 장의 카드로 바꾸면 측정 정보가 달라진다. 토스처럼 보이게 하려고 척도를 이지선다로 축소하지 않는다. 흥미·최근 행동·환경 선호는 서로 다른 질문이므로 모두 같은 ‘그렇다/아니다’ 문구로 통일하지 않는다.

**대표 문항의 화면 문구 예시 — 제안이며 아직 적용하지 않음**

장 안내: `어떤 활동에 마음이 가나요?`

질문: `누군가 어려워하는 내용이나 방법을 이해하기 쉽게 설명하는 일`

보조 문구: `얼마나 잘하는지보다, 얼마나 해보고 싶은지 생각해 주세요.`

응답: 기존 1~5 값을 유지하고, `1 전혀 하고 싶지 않다 / 3 중간 / 5 매우 하고 싶다`를 함께 표시한다. `판단하기 어려워요`는 숫자와 분리한다. 문항 의미나 중간값의 설명을 새로 바꾸는 경우에는 별도 문구 검토가 필요하다.

이 예시는 원래 R3-04 문항을 활용한다. 새 상황형 문장으로 갈아 끼우지 않고 화면 안내를 통해 읽기 쉽게 만드는 접근이다.

## 5. 에듀핀에 맞는 시각 방향

추천 분위기는 **차분하고 친근한 진로 안내**다. 현재 색상과 한국어 말투를 바탕으로 밀도와 위계를 개선한다.

| 요소 | 적용 제안 |
|---|---|
| 색상 | 기존 밝은 배경 `#FAFAF8`, 진한 본문 `#202422`, 파란 강조 `#2564A4` 활용. 파란색은 현재 진행·선택·주요 행동에 집중 |
| 질문 영역 | 데스크톱 최대 폭 520~600px, 모바일 좌우 여백 20~24px를 초기 설계값으로 사용 |
| 글자 | 질문 24~28px, 선택지 16~18px. 긴 문장과 보기 본문은 왼쪽 정렬 |
| 선택 영역 | 최소 높이 56px, 보기 간격 10~12px, 모서리 12~16px를 초기값으로 검토 |
| 선택 상태 | 테두리 + 배경 + 체크 표시. 색만으로 선택을 전달하지 않음 |
| 7점 선택 | 각 값의 누를 영역을 확보하고 ‘판단 어려움’은 별도 줄에 배치. 좁은 화면에서 잘리면 표현을 재배치 |
| 주요 버튼 | 화면 하단에서 위치를 예측할 수 있게 배치하되 입력창·키보드·긴 내용을 가리지 않도록 구성 |
| 그림 | 시작, 장 전환, 결과에 제한적으로 사용. 답변마다 가치판단을 암시하는 표정이나 이미지를 붙이지 않음 |
| 움직임 | 짧은 선택 확인과 부드러운 전환. 시간 지연을 넣어 분석이 정교한 것처럼 연출하지 않음 |

위 수치는 토스에서 측정한 값이 아니라 에듀핀 설계를 시작하기 위한 제안값이다. 기존 내부 ID와 문항판 표시는 검토 화면에서 유지하고, 일반 응답 화면에서는 질문 이해에 필요한 내용에 우선순위를 둔다.

접근성 측면에서는 질문 제목·입력 레이블·키보드 포커스·진행 변경 안내를 연결해야 한다. 자동 전환 시 사용자가 읽던 위치를 잃지 않게 하고, 동작 축소 설정을 존중한다. 토스 화면에서 보인 옅은 답변 글씨와 이미지 중심 결과는 그대로 복제하기보다 가독성과 텍스트 접근을 보완할 부분이다. 결과 카드의 대체 텍스트는 유형명 수준으로 확인되어, 본문 설명에 대한 동등한 텍스트 제공은 별도 확인이 필요하다.

## 6. 결과는 첫 요약과 상세 해설을 연결한다

에듀핀 결과 첫 화면은 다음 순서를 권한다.

1. 현재 응답을 설명하는 제목 한 줄. 예: `새로운 표현을 구상하고, 사람의 이해를 돕는 활동에 마음이 가요.` 실제 해당 응답 근거가 있을 때만 표시한다.
2. 핵심 요약 3개. 흥미, 편한 업무·환경, 추가로 확인할 조건을 구분한다.
3. 6영역 흥미 프로필과 읽기 쉬운 해설. 그래프는 능력·우열·채용 적합률로 설명하지 않는다.
4. 관심 분야에서 살펴볼 점과 근거. 추천 방향, 경험 여부, 필수 조건은 별도 내용으로 보여준다.
5. 다음 행동 하나. 예: `상담 전에 확인할 질문 보기`. 저장은 보조 행동으로 둔다.

고정 유형명 하나로 모든 답을 대체하지 않는다. 캐릭터를 도입하더라도 ‘현재 답변의 특징을 기억하는 이름’으로 한정한다. 기존 6영역 프로필은 네 숫자 응답이 모두 있어야 해당 영역 평균을 표시하며, 부족한 영역은 확인 전으로 둔다.

결과를 이미지로 내려받게 하더라도 본문은 웹 텍스트로 제공한다. 본인용 요약 저장과 채용처 전달은 각각 명확한 동작으로 설계하고, 채용처 공유에서는 기존 동의·검토 흐름을 이어간다. 실명·원응답·급여·연락처 등이 들어간 결과를 한 번의 ‘공유’로 모두 노출하는 구조는 피한다.

## 7. 적용 순서와 단축판의 위치

**1차: 기존 문항을 유지한 사용자 경험 개선**

시작 화면 → 진행·이전·수정 → 척도별 화면 → 임시 저장·복구 → 결과 첫 요약 순으로 구현한다. 문항 분기와 필수 후속 응답이 빠지지 않는지도 확인한다. 첫 단계에서 문항 수까지 동시에 줄이면 화면 개선과 문항 변경의 효과를 구분하기 어렵다.

**2차: 순서와 화면 묶음의 사용성 확인**

실제 대상자 5~8명에게 첫 화면, 5점·7점·상황형, 중단·복귀, 결과 이해를 살펴보는 소규모 사용성 시험을 제안한다. 이 인원은 문제를 찾는 탐색용이며 완주율 향상이나 측정 타당도를 입증할 규모를 뜻하지 않는다. 장별 이탈, 응답 시간, 수정 빈도, 판단 어려움 선택, 저장 복구 실패를 관찰한다. 기간·기기별 시간 분포를 확보한 다음 예상 소요시간을 안내한다.

**3차: 유입용 체험판이 별도로 필요할 때**

8~12문항의 짧은 체험판은 별도 제품으로 검토할 수 있다. 결과는 관심 방향과 다음 탐색 안내에 한정하고, 현행 전체 질문지의 결과·점수·매칭 정확도를 그대로 제공한다고 표현하지 않는다. 현재 R3는 24문항, 영역당 네 응답을 요구하므로 임의로 줄여 동일 결과를 산출할 수 없다. 정식 단축판은 별도의 문항·해석 설계와 검증이 필요하다.

## 8. 관찰 범위와 한계

- 토스는 가상 닉네임·가상 선택으로 하나의 완주 경로와 한 결과 유형을 확인했다. 전체 결과 유형, 분류 알고리즘, 다른 답변 경로는 확인하지 않았다.
- 에듀핀 공개 화면의 시작·흥미 영역을 시각적으로 확인하고, 로컬 정의에서 현재 분기와 문항 수를 대조했다. 이번 작업에서 에듀핀 전체 응답이나 기능 회귀 검사를 수행하지 않았다.
- 데스크톱 브라우저 관찰이다. 실제 모바일 기기, 화면낭독기, 대비 수치, 200% 확대, 동작 축소의 전체 검증은 수행하지 않았다.
- 토스 후속 화면의 행사 날짜는 캠페인 문구로만 관찰했으며, 현재 행사 운영 여부를 확인하거나 행사 참여를 추천한 것이 아니다.
- 완주율, 응답 품질, 채용 결과 향상에 관한 제안은 검증할 가설이다.
