# Edupin reports · revised v3.5

2026-09-07 · 지원자 중복 경험 질문 삭제 및 경험 해설 통합 · 현장 검증 전 로컬 검토본

## 웹 배포

- 공개 주소: https://edupin-questionnaire.vercel.app
- Vercel 프로젝트: `edupin-questionnaire` · 프로덕션
- 기본 경로 `/`에서 지원자 질문지를 표시합니다. 입력 후 “입력한 답으로 결과 초안 보기”로 현재 답변의 결과를 생성합니다.
- 지원자 입력만으로 본인 결과를 볼 수 있으며, 같은 화면에서 채용처 질문도 입력하면 직무 비교 결과를 함께 볼 수 있습니다.
- 응답은 브라우저 메모리에서 처리합니다. 서버 저장·접수·발송은 없으며 새로고침 시 입력이 사라집니다.
- `vercel.json`은 `npm run build`로 생성한 `preview/`를 배포합니다. 재배포: `vercel deploy --prod --scope nextiproject-2296s-projects`.
- 2026-09-07: 공개 루트·JS·CSS·결과지·안내 문서 HTTP 200 및 실제 브라우저의 답변 수정→결과 생성→채용처 비교 동작을 확인했습니다.

## 선택한 질문지의 가상 응답과 결과

- 상단에서 지원자 또는 채용처 질문지를 선택한 뒤, 해당 대상의 “가상 응답 채워 검토하기”를 누르면 그 질문지만 채우고 결과를 바로 표시합니다.
- 다른 질문지의 입력은 유지합니다. 입력 비우기도 현재 선택한 질문지에만 적용합니다.
- 채용처만 입력한 경우 직무·조직 운영 응답 요약을 보여주며, 양쪽을 각각 입력한 경우 기존 지원자 비교 결과를 볼 수 있습니다.
- 결과의 미응답·입력 오류 개수는 현재 결과 대상의 질문지를 기준으로 표시합니다. 입력 변경 후에는 이전 결과를 숨기고 다시 계산합니다.

## 최근 질문지 수정

지원자 기존 17번(K3-07)을 삭제했습니다. 03번(F3-3)의 경험 활동, 04번(F3-4)의 전체 활동 기간, 05번(F3-5)의 협업·고객관계를 추천 분야와 채용처 경험 해설에 함께 사용합니다. 나머지 문항의 ID와 선택지는 유지하고 화면 번호만 이어 붙였습니다. 기본 127묶음, 아동 접촉 시 131묶음입니다.

관련 활동을 선택한 경우 관련 경험을 표시하며, 선택하지 않은 분야는 미확인으로 남깁니다. 전체 활동 기간을 특정 분야의 경력 기간으로 바꾸거나 교육 활동을 아동·성인 직무의 직접 경험으로 확정하지 않습니다. 과거 K3-07 응답은 내부 비활성 원문으로만 보존하고 분석에 사용하지 않습니다.

## v3.5: 6영역 프로필

지원자 결과지 앞부분과 에듀핀 내부 결과에 현실형·탐구형·예술형·사회형·진취형·관습형의 응답 평균을 육각형으로 보여주는 ‘6영역 프로필’을 추가했습니다. 고정된 순서와 숫자 표를 함께 두어 여러 결과를 보더라도 같은 위치에서 비교할 수 있게 했습니다.

여섯 영역이 모두 계산된 경우에만 면을 이어 보여줍니다. 응답이 부족한 영역은 ‘확인 전’으로 남기며 다른 점으로 임의 연결하지 않습니다. 그래프는 활동 흥미를 요약하며 능력·성격 등급·채용 적합도를 뜻하지 않습니다. 채용처 결과지에는 표시하지 않습니다.

## v3.4: 채용처에는 중요한 특성을 한 번만, 문항 근거는 에듀핀에만

채용처 첫 요약의 왼쪽을 ‘답변에서 파악한 지원자의 특성’, 오른쪽을 ‘채용 전 확인할 점’으로 정리했습니다. 행동을 설명하는 긴 문장과 같은 내용을 아래 장에서 다시 반복하지 않습니다. 중요 조건과 부합 설명은 크게 유지하고, 분야 경험과 전체 업무 조건은 컴팩트한 참고 영역으로 옮겼습니다.

채용처 화면에서는 ‘궁금하다면, 어떤 답에서 나왔는지 보기’와 문항 ID를 표시하지 않습니다. 승인 후 반환하는 `reports.employer` 데이터에서도 `source_ids`, 내부 문항 `id`, `employer_id`를 재귀적으로 제거합니다. 에듀핀 내부의 `reports.edupin`과 `employer_drafts`에는 근거를 그대로 보존합니다.

‘이 자리’처럼 대상을 뭉뚱그린 표현은 채용처 문장에서 ‘모집 직무’ 또는 ‘현재 모집 직무’로 바꿨습니다. 질문·계산·추천·동의·공유 승인 기준과 지원자·에듀핀 해설 내용은 바꾸지 않았습니다.

## v3.3: 채용처가 여러 지원자를 같은 기준으로 빠르게 읽는 첫 화면

채용처 결과의 맨 위에 중요 조건 부합 개수와 검토 상태를 고정된 요약판으로 배치했습니다. 그 아래에는 ‘이 자리에서 기대할 강점’과 ‘약점으로 단정하기 전, 확인할 점’을 나란히 보여줍니다. 중요하게 고른 각 조건은 채용처의 답과 지원자의 답이 어떻게 만나는지 사람이 설명하듯 풀어 씁니다.

모든 중요 조건이 같은 방향일 때에는 “중요하게 고른 3가지 조건에 모두 부합하는 지원자입니다”처럼 바로 말합니다. 다만 이 표현은 같은 질문에서 선호 방향이 일치했다는 뜻입니다. 비교 집단이 없는 단일 결과에 ‘가장’이라는 순위를 붙이지 않고, 능력·성과·채용 성공률을 뜻하는 적합도 퍼센트도 만들지 않습니다. 경험 요건·필수 근무 조건·미확인 답변이 있으면 부합 문장보다 먼저 표시합니다.

질문·계산·추천·공유 판정은 v3.1, 지원자와 에듀핀의 해설 내용은 v3.2와 같습니다. v3.3에서 새로 만든 것은 채용처용 `reading.overview`, 조건별 `reading.condition_stories`, 그리고 이를 보여주는 비교형 레이아웃입니다.

## v3.2: 중요한 이야기를 먼저, 편안하게 설명하는 해설

v2.0의 이야기 흐름을 참고해 지원자·에듀핀·채용처의 첫머리, 제목, 연결 문장과 다음 행동 안내를 다듬었습니다. 반복되는 계산·근거 설명은 펼쳐보기로 옮겼지만, 필수 조건의 차이와 답변 부족·경험 요건·안전 확인은 눈에 보이게 남깁니다. 에듀핀의 전체 37항목 표와 모든 원응답은 그대로 볼 수 있습니다.

입력과 분석 버전은 **3.1**, 현재 해설 표현 버전은 **3.5**입니다. 문항·평균·추천 규칙·동의·공유 판정은 바꾸지 않았습니다. v3.5는 기존 여섯 흥미 평균의 표시 방식만 추가합니다. 웹 미리보기는 `reading` 필드를 읽습니다. 질문 수를 더 줄이거나 서술형 의미 분석을 추가한 개정이 아닙니다.

## 현재 문항 구성

v3.0 화면 번호 29·34·45·48·49·50번을 제외했습니다. 활동 흥미는 여섯 영역에 각각 4문항, 총 24문항입니다. 나머지 문구·내부 ID와 채용처 질문은 유지했고 화면 번호만 연속 재부여합니다. 중복 경험 문항을 추가로 삭제한 현재 지원자 질문은 기본 127묶음, 아동 접촉 시 131묶음입니다(선택 서술 2개 포함, 추가 입력란은 별도).

흥미 평균은 삭제 문항을 제외한 네 응답으로 계산합니다. 숫자 답변이 최소 네 개 있어야 한다는 기존 원칙을 유지하므로, 한 문항이라도 미응답·판단 어려움이면 그 영역의 평균은 보류됩니다. 여섯 흥미 요약값은 단축판임을 표시합니다. 기존 3.5 탐색 기준은 잠정 유지했으며, 구판과 같은 추천·측정 정확도를 보장하지 않습니다. 이번 작업에 새 해석 기능이나 서술형 자동 분석은 추가하지 않았습니다.

## 현재 범위

질문 정의 → 입력 검증 → 응답 요약 → 근거 연결 해석 → 직무별 조건 대조 → 대상별 리포트의 흐름이 연결되어 있습니다.
미리보기는 동일한 엔진으로 생성하며, 지원자의 경력이나 점수를 별도로 꾸며 넣지 않습니다.

질문지 화면에서 직접 입력한 값은 해당 브라우저 페이지의 메모리에만 있습니다. 새로고침하면 사라집니다. 서버 저장, 실제 등록, 채용처 발송, 로그인·권한 관리 서비스는 포함하지 않습니다.
가상 응답을 채우는 버튼은 기존 입력을 대체하기 전에 확인합니다.

## 실행

Node.js의 기본 모듈만 사용합니다. 별도 패키지 설치 없이 다음을 실행할 수 있습니다.

```sh
npm test
```

- `npm run validate`: 분석·매칭·공유 조건, 경험 문항 통합, 현재 결과 기준·해설 경계 검사
- `npm run build`: 질문지 문서, 미리보기, 문항 변경표, 가상 결과 재생성
- `node tests/browser-validation.js /absolute/path/to/jsdom`: jsdom이 있는 환경의 화면 동작 검사. UI 검사에만 별도 jsdom이 필요합니다.

소스 원본은 `engine/schema.js`, `engine/assessment.js`, `engine/interpretation.js`, `engine/matching.js`, `engine/reports.js`입니다.
해설의 표현은 `engine/reading.js`, 읽기 순서와 표시 방식은 `tools/reading-layout.js`, 해설 스타일은 `tools/styles.css`의 v3.2·v3.3·v3.4·v3.5 구간에서 관리합니다. 채용처 공유 데이터의 내부 식별자 제거는 `engine/reports.js`의 `employerShare()`가 담당합니다. 경험 해설의 공통 처리기는 `engine/experience.js`이며, `interpretation.js`·`matching.js`·`reports.js`에서 사용합니다. 점수 계산을 담당하는 `engine/assessment.js`는 v3.1 원본과 동일합니다. `engine/schema.js`에는 채용처 16–27번(HJ)의 질문을 “이 직무의 실제 업무와 더 가까운 쪽을 골라주세요”, 28–39번(HE)의 질문을 “우리 조직의 실제 운영과 더 가까운 쪽을 골라주세요”로 수정했습니다. 지원자는 K3-07을 삭제하고 경험 해설의 입력을 F3-3·4·5로 통합했습니다. 흥미·행동 점수와 업무 조건 대조 규칙은 유지합니다.
자동 생성된 `preview/`, `fixtures/`, `docs/applicant-questionnaire.md`, `docs/employer-questionnaire.md`, `docs/change-impact.md`, `docs/report-layout.md`를 직접 수정하지 마세요.
`reference/`는 v2.0의 동결된 문항·척도 정의입니다. 제외 문항을 보존한 참고 자료이며 활성 질문지가 아닙니다. v3.1에서도 B3 문항을 제시하거나 계산하지 않습니다.

## 데이터 계약

```js
const { run } = require('./engine/reports');
const output = run({
  version: '3.1',
  responses: {},
  positions: [{ version: '3.1', position_id: 'POSITION-ID', responses: {} }],
  assessed_at: 'YYYY-MM-DD',
  conditions_updated_at: 'YYYY-MM-DD',
  now: 'YYYY-MM-DD',
  consent: { matching: false, employer_position_ids: [] }
});
```

숫자 문항은 정수 number, 판단하기 어려움은 `U`, 단일 선택은 선택지 문자열(분야는 코드), 복수·순위 선택은 선택 순서대로 배열, 묶음 입력은 정의된 키를 가진 객체입니다.
추가 응답은 `문항ID__evidence`, `__reason_tags`, `__free_text`, `__neutral_reason`, `__norm_checked`, `__policy`로 전달합니다.
구판 버전 또는 버전 없는 입력은 자동으로 호환하지 않습니다. 임의의 외부 키는 분석하지 않고 내부 비활성 데이터 목록에 남깁니다.
이 패키지의 입력 버전은 지원자·채용처 모두 3.1입니다. 현재 로컬 개정본에는 채용처 HJ·HE 문구 수정과 지원자 K3-07 삭제가 포함됩니다. v3.0에서 유지한 개별 문항의 의미도 그대로지만 흥미 척도 구성이 달라졌으므로, 과거 평균을 재사용하거나 버전 번호만 바꾸어 검토 승인을 이어가지 않습니다. 원응답의 판본·날짜를 보존한 재계산·검토 절차는 운영 연결 시 별도로 설계해야 합니다.

반환값:

- `reports.applicant`: 본인용 결과
- `reports.edupin`: 전체 근거, 원응답, 자리별 대조, 공유 전 채용처 초안
- `reports.employer`: 동의·현재 응답에 연결된 검토 승인·완결성·신선도 등의 조건이 충족된 결과만 반환. 내부 문항 ID와 근거 ID는 제외하며, 반환되어도 실제 발송하지 않음

각 대상의 `reading.version`은 `3.5`이며, 본문 첫 설명·문단·근거를 담습니다. `reports.edupin.employer_drafts[*].reading`은 에듀핀 검토용 근거 ID를 유지하지만 개인정보를 가린 채용처용 문장만 사용합니다. 에듀핀 내부 원문을 채용처 문장으로 옮기지 않습니다. 네 가상 사례의 분석·매칭·공유 결과를 경험 문항 통합 후 기준과 자동 대조합니다. 변경 전후 흥미·행동 점수, 추천 방향, 업무 조건 대조는 유지됐으며 경험 해설과 관련 근거·문항 수는 갱신했습니다.

이 데이터 계약은 서버 인증·접근 제어를 대신하지 않습니다. 브라우저가 보낸 승인값을 실서비스에서 신뢰하면 안 됩니다. `review`와 `consent`는 서비스의 권한 있는 저장소에서 서버가 확인하고 공급해야 합니다. 검토 승인은 `snapshot()`으로 만든 현재 지원자·직무 응답의 스냅샷과 연결되어야 하며, 응답 변경 후에는 다시 검토합니다.
